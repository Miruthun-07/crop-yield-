      Linear Regression

      A simple weighted-sum baseline.

      How it works: Fits a straight-line equation y = β₀ + β₁x₁ + … + βₙxₙ that minimises the squared error between predicted and actual yield.

      Advantages: Highly interpretable, fast to train, easy to debug, and provides a strong baseline.

      Limitations: Cannot model non-linear relationships (e.g. rainfall saturation) without feature engineering; sensitive to outliers and multicollinearity.

      Random Forest Regressor

      Ensemble of decorrelated decision trees.

      How it works: Trains many decision trees on bootstrapped samples and averages their predictions to reduce variance.

      Advantages: Captures non-linearities and interactions, robust to outliers, requires minimal preprocessing, offers feature importance.

      Limitations: Larger memory footprint, slower inference than a single tree, less interpretable than linear models, can overfit noisy data.

      Gradient Boosting Regressor

      Sequential error-correcting trees.

      How it works: Builds trees one at a time, each new tree correcting the residual errors of the combined ensemble so far.

      Advantages: Strong predictive accuracy on tabular data, handles mixed feature types, supports custom loss functions.

      Limitations: Sensitive to hyper-parameters (learning rate, depth, n_estimators), prone to overfitting without regularisation, slower to train.

      XGBoost Regressor

      Regularised gradient boosting.

      How it works: A highly optimised implementation of gradient boosting with regularisation, missing-value handling, and parallel tree construction.

      Advantages: State-of-the-art on many tabular benchmarks, handles missing data natively, supports early stopping and GPU acceleration.

      Limitations: Complex parameter space, less interpretable, can be brittle to distribution shift if retraining is not done carefully.

      Input Factor Importance (Illustrative)

      Heuristic influences

      Rainfall Influence

      Rainfall drives yield up to a crop-specific optimum (e.g. rice ~1200–2000 mm, millet ~400–700 mm). Beyond saturation, additional rainfall harms yield through waterlogging and nutrient leaching.

      Temperature Influence

      Most crops thrive in 20–30°C. Below 15°C slows metabolism; above 35°C causes heat stress and pollen damage. Perennial plantations tolerate wider ranges than cereals.

      Soil pH Influence

      Optimal pH is 6.0–7.0 for most crops. Strongly acidic (<5.5) or alkaline (>8.5) soils lock up nutrients and reduce microbial activity.

      Nutrient Influence

      Nitrogen drives vegetative growth, phosphorus supports rooting and flowering, and potassium improves stress tolerance. Balanced NPK gives a multiplicative boost.

      Irrigation Influence

      Drip and sprinkler systems deliver water efficiently and boost yield; rainfed farming is more variable; flood irrigation can waterlog sensitive crops.

      Humidity Influence

      60–80% humidity supports healthy transpiration. Excessively high humidity increases fungal disease pressure; very low humidity stresses plants.

      Project Objective

      The Intelligent Crop Yield Forecasting and Agricultural Decision Support System is an academic AIML project that demonstrates how historical agricultural data, environmental sensors, and explainable analytics can be combined to help farmers, extension officers, and policymakers reason about expected crop yield.

      The front-end dashboard you are using lets a user enter field conditions, receive an estimated yield, explore scenario simulations, inspect the influence of environmental factors, compare ML models conceptually, and persist their predictions to a cloud database for later review.

      Methodology Pipeline

      1. 1
        Historical Agricultural Data

        Crop, season, state, area, production, fertilizer, pesticide and yield records are collected — in this demo, 19,689 records spanning 1997–2020 across 30 Indian states.

      2. 2
        Data Preprocessing

        Outlier filtering, missing value handling, crop-name normalisation, and aggregation per (crop, state, season) tuple.

      3. 3
        Model Training

        Regressors such as Linear Regression, Random Forest, Gradient Boosting, and XGBoost are trained on the prepared feature set.

      4. 4
        Model Evaluation

        Models are compared using MAE, RMSE and R². These metrics are intentionally shown as unavailable here because no trained backend is connected to this demo.

      5. 5
        Yield Forecasting

        Trained models predict yield for new inputs. In this front-end demo a transparent deterministic estimator grounded in historical averages is used and clearly labelled.

      6. 6
        Explainable AI

        Feature importance / SHAP analysis explains which inputs drove a prediction. The demo here shows illustrative heuristic influences instead.

      7. 7
        Agricultural Decision Support

        Recommendations on soil testing, irrigation, drainage and extension outreach are generated from rule-based heuristics.

      Core Concepts & Algorithms

      • Supervised regression — predicting a continuous target (yield in tonnes/ha) from structured inputs.
      • Ensemble learning — combining multiple models (Random Forest, Gradient Boosting) to reduce variance and bias.
      • Feature engineering — deriving environmental factors (pH suitability, rainfall saturation) from raw inputs.
      • Explainability — surfacing the contribution of each feature to a prediction, in this demo via illustrative heuristics.
      • Evaluation metrics — MAE, RMSE and R² to quantify predictive accuracy.

      Honest Limitations

      This front-end demo does not perform genuine machine learning inference. The “Demo Estimate” badge on every result makes this explicit. Genuine ML predictions require an appropriate historical dataset, trained models, and a backend that exposes them — none of which are bundled with this static website.

      No fake accuracy scores or evaluation metrics are displayed. The model comparison table shows “Evaluation unavailable — trained models not connected” until real evaluation results are supplied.
